===============================================================================
AUTHENTICATION
===============================================================================

All endpoints (except marked [PUBLIC]) require:
  - requireAuth middleware
  - Valid JWT token in Authorization header
  - Scoped to beautician_id (req.beautician.id)

Public endpoints:
  - GET /api/consultation-forms/public/:token
  - GET /api/booking/:slug
  - POST /api/webhooks/whatsapp
  - POST /api/webhooks/twilio-sms
  - POST /api/stripe/webhook

===============================================================================
COMMON PATTERNS
===============================================================================

CRUD Operations:
  Most features follow standard REST:
  - GET /resource           - List all
  - POST /resource          - Create
  - PATCH /resource/:id     - Update
  - DELETE /resource/:id    - Delete

Resource Filtering:
  - Query params (e.g., ?date=YYYY-MM-DD)
  - Scoped to beautician_id automatically

Request Body:
  Most POST/PATCH endpoints accept JSON with table-specific fields.
  Common fields: date, status, completed, notes, amount, etc.
  Many endpoints use Zod validation (see middleware/validate.js)

Response Format:
  Success: HTTP 2xx with JSON data
  Errors: HTTP 4xx/5xx with { error: "message" }
