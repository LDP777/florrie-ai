Critical Findings

Critical   PostgREST Filter Injection in .or() Queries

Files: clients.js:78, webhooks.js:344

User-supplied search text is interpolated directly into Supabase .or() filter strings. Because PostgREST parses the comma-separated filter syntax, an attacker can inject additional filter clauses.

// clients.js — current code
query = query.or(`first_name.ilike.%${req.query.search}%,last_name.ilike.%${req.query.search}%`);

// Attack: GET /api/clients?search=x,beautician_id.eq.ATTACKER_UUID
// Injects a filter that returns another beautician's clients

Same pattern in webhooks.js:344 where phone numbers flow into .or() without sanitisation.

Fix: Strip all non-alphanumeric/space characters from search input before interpolation. Or use Supabase's individual .ilike() calls chained with separate queries.

High Severity

High   Missing Input Validation on Financial Endpoints

Files: money.js POST /expenses, treatments.js POST/PATCH

The expenses endpoint accepts amount_cents as any integer — including negatives. A user could log negative expenses to inflate profit figures. Similarly, treatment prices and durations have no Zod schema and accept any value.

Fix: Add Zod schemas: amount_cents: z.number().int().min(1), price_cents: z.number().int().min(50), duration_minutes: z.number().int().min(1).max(480).

High   Unvalidated AI Output Parsed as JSON

Files: money.js:337, ai-front-desk.js:250,585

Claude API responses are parsed with JSON.parse() then used without structure validation. If Claude returns malformed or unexpected fields, downstream code trusts it blindly. Prompt injection via business context (client names, notes) could manipulate the AI output.

Fix: Add a Zod schema after every JSON.parse() of AI output to validate expected fields exist and are the right type.

High   npm Dependency: path-to-regexp DoS (CVE)

Package: Backend indirect dependency via Express

Known high-severity ReDoS vulnerability in path-to-regexp < 0.1.13. Crafted route patterns can hang the event loop.

Fix: cd backend && npm audit fix

Medium Severity

Medium   Inconsistent Zod Schema Coverage

Routes like treatments.js, content.js, ai-actions.js, and parts of appointments.js skip Zod validation entirely. Query params like limit, page, per_page use raw parseInt() with no upper bound — setting ?limit=999999 could cause a performance DoS.

Medium   Idempotency Guard is In-Memory Only

The payment idempotency Map lives in process memory. Survives neither server restarts nor multi-instance deploys. On Railway's single-instance trial this is fine, but if you ever scale horizontally, duplicate payments become possible.

Medium   No Appointment Time Validation Against Working Hours

Bookings don't check whether the requested time falls within the beautician's working_hours. A crafted API call could create appointments at 3am.

Medium   No Token Revocation / Session Blacklist

JWT tokens are validated via Supabase but there's no revocation mechanism. If a token leaks, it stays valid until natural expiry. Supabase handles this at their layer, but no application-level blacklist exists.

Medium   CSP Allows 'unsafe-inline' for Styles

The Content Security Policy includes style-src 'unsafe-inline'. While needed for many React patterns, it weakens CSP's protection against injected CSS.
